### 1.2 节点卡片（视频节点，右下）—— 自上而下

1. **标题行**：最左一个**小三角形 ▶**（折叠/展开控件），文字 `视频节点 1 - 副本`；标题行**右端**是尺寸 `1280 × 720`。
2. **卡片主体**：整块被视频预览占满（近景虚焦人脸，暖棕肤色）。
   - **左上角**：半透明徽章 `AI生成`。
   - **右上角**：一个小方形图标（我读作「叠放 / 菜单」符号，**语义不明**）。
   - **左右两侧竖直中线**：各一个圆形**连接端点**（左侧端点接出了连线）。
3. **卡片底部（预览内）**：播放三角 · `0:00` · 进度条（白色圆形滑块靠近起点）· `0:30` · 音量喇叭 · 右端一个方框（设置/全屏类）图标。
4. **卡片下方**：参数 chip 行（被下方大面板遮住一半），可辨认 `16:9 · 720P · 30s · 1个…`，左侧还有一项以比例/模型开头（`2.5…`）与 `全能参考`。

> ⚠️ 关键：**视频卡片底部只有播放控制，没有「下载 / 设为主图」这类动作按钮**。带「下载 / 设为主图」的是**上方图片卡片**。

### 1.3 卡片上的动作条

- **图片卡片**：卡面直接带 `下载`、`设为主图`（另有一张是 `下载`、`收起`）——都是**小号深色圆角按钮，贴在卡上**，不是浮动长条。
- **视频节点**：`高清 / 片段重拍 / 逐帧拉片 / 智能去字幕 / 音视频分离 / 主体消除 / 创意片头` —— 一条**横向浮动动作条**，7 项以纯文字为主，紧贴视频节点。

> DOM 里这 7 项**出现了两遍**（`scan.log` 行 10–11），说明画布上**至少有两个视频节点**，各自带一条同样的动作条——不是一条更长的条。

### 1.4 参数的表达方式

- **节点参数**：贴卡片下方的一行 chip，`·` 分隔（`16:9 · 720P · 30s · 1个`）。
- **提示词面板底部参数行**：`2.5`（**带黄色菱形图标 + 下拉箭头**，是模型/版本位）· `全能参考`（带下拉）· `16:9` · `720P` · `30s` · `1个`。前两项是**下拉控件（chip 形状）**，后四项是**纯参数 chip**。
- 记一点：**模型位与「参考模式」位是并列的两个下拉**，层级上等价于我们「模型 chip + 一行参数摘要」。

### 1.5 时间轴类交互

- 视频预览底部是**线性进度条 + 当前/总时长**（`0:00 / 0:30`），滑块在起点。
- 配套**帧级操作**：`截取当前帧 / 截取首帧 / 截取尾帧`（DOM 原文；运行时与进度条同属视频节点）。
- DOM 里还夹着一个孤立的 `50`（`… 0:30 50 截取当前帧 …`），**不确定**它是帧数、时长档还是别的。

### 1.6 工具栏 / 资产区

- **左下**：`资产管理` 入口 + 4 个图标（四宫格=网格/视图、定位针=小地图、节点连接、链环）+ `40%` 缩放数字。**没有侧栏**，是贴着左下角的一行。
- **底部中央**：悬浮操作栏（新增/选择/添加节点/表情/历史/键盘帮助/帮助）+ 一个**彩色圆形入口**。
- 我们自己的历史抓取（`docs/libtv-refactor-checklist.md` §A4）把这条底部中央 dock 记为：`添加节点 | 移动 | 素材库 | 角色造型室 | 生成历史 | 快捷键 | 教程 | ● TV Director`。即 **TV Director 是底部中央 dock 上的一个「●」入口，不是右上角**。

### 1.7 右下提示词大面板（细节）

- **顶部**：直接就是能力标签行 `＋参考 / 标记 / 特效 / 角色库 / 运镜`（带图标的深灰胶囊），最右上还有一个**斜向外扩**的图标按钮（展开/放大）。**没有标题栏，也没有「下载 / 收起」**。
- **中部**：1 张参考缩略图（左上角黑色圆形编号 `1`，右下角一个**蓝色盾牌**标记，**语义不明**）+ 一整段中文提示词（我记得开头是「一支时长30秒的高定时装香水广告，一镜到底…」）。
- **底部**：参数行 `2.5 / 全能参考 / 16:9 / 720P / 30s / 1个`。
- **发送**：右下角**白色圆形按钮**，内是向上箭头（截图里只露出上半）。

### 1.8 Agent 入口的形态

- **在这张图里看不到**：菜单收起，图上既没有展开的下拉，也没有写着 Agent 的按钮（它在底部中央 dock 里，就是那个「● TV Director」）。

## 3. 复刻清单（按优先级）

### P1 — 立刻抄（结构/交互，改动小、复用已有数据模型）

**P1-1 图片产物的「下载 / 设为主图」**
- 抄的是**结构**：产物卡上给两个一级动作；「设为主图」改变该节点的「代表图」（批量组里的 primary）。
- 落地文件：`src/views/workflow/components/nodes/ImageNode.vue`（加进 `CanvasNodeTopToolbar` 的 `toolbarItems` 或 hover 条）；写入走 `composables/useWorkflowCanvas.ts` 的 `updateNode(id, { primaryImageId })` —— **数据模型已经存在**。
- 验收：多图节点点「设为主图」后主图切换、刷新后仍在（写进 `node.data`）；「下载」落盘文件名稳定；为 primary 切换写一条纯逻辑单测。

**P1-2 Agent 空态改成「按场景起手」**
- 抄的是**结构**：入口常驻 + 若干**完整句子**的场景项，点了把整句填进输入框（**不自动发送**）。
- 落地文件：`src/components/canana/RightPanel.vue` 的 `examplePrompts`（换成 4–5 条**我们自己的**场景句）、`src/components/canana/SidebarEmptyState.vue`。
- 验收：空态能一键填句；点完仍可编辑再发；文案自查**不含他们的独家命名**（见文末）。

**P1-3 视频节点补一条动作条（先只放有管线的项）**
- 抄的是**结构**：视频产物选中时出现一条横向动作条。
- 落地文件：`src/views/workflow/components/nodes/VideoNode.vue`（引入 `CanvasNodeTopToolbar.vue` + `composables/useNodeToolbar.ts`，与 `ImageNode.vue` **同一套**），再加 `toolbarItems`。
- 验收：只摆**真能跑**的项；反缩放/贴边收敛与图片节点一致；`tests/node-toolbar.test.ts` 不退。

### P2 — 以后再说（要后端或新交互）

**P2-1 图片批量组 2×2**：`ImageNode.vue` + 新组件渲染 `batchChildren`，每张带 下载/设为主图。验收：多图不再叠成一张、选中进预览、primary 有唯一标记。
**P2-2 视频时间轴 + 截帧**：`VideoNode.vue` + 截帧工具。验收：拖动 seek 准；截出的帧落成一个新 image 节点并走已有 upload 管线。
**P2-3 画布内「资产管理」抽屉**：把 `AssetManagement.vue` 的能力以抽屉挂到左下。验收：抽屉里选素材能直接落成 `AssetNode`。
**P2-4 场景入口做成数据类型**（不是写死数组），让后台可配。验收：新增场景不改组件。

### P3 — 抄结构但要谨慎

**P3-1 底部中央 dock**：把「左侧 rail」与「底部 dock」的职责重划一次，含「● Agent」入口。落地：`src/views/workflow/index.vue` + `src/components/canvas/CanvasDockToolbar.vue`（目前是 dead code）。验收：只搬**入口分区**，不搬他们的会员/红包/教程 chrome。

### 「抄结构」与「抄皮」的分界（贯穿每一条）

- **抄（结构/交互范式）**：卡片分区顺序、动作条**贴卡片**出现、参数压成**一行 chip**、时间轴形态、入口的「常驻 + 场景句」、批量组的「可设主图」。
- **不抄（皮）**：
  - **视觉资产**：他们的图标、缩略图、渐变、Logo、动效资源；
  - **独家命名**：角色造型室、TV Show、**全能参考**、感知画布开始创作、TV Director、双节红包；
  - **文案原句**：一律重写。
- 这条规矩我们已经在 `docs/libtv-interaction-spec.md`（§5「自己画 path，不要抄第三方站点的 SVG 数据」）立过，本清单沿用。

## 4. 不该抄的 / 抄了会害我们的

1. **广场式信息架构**（底部 `素材库/角色造型室/生成历史/教程` + 顶栏 `分享/会员/红包/积分` + 独立资产页）
   → 这是「什么都有」的内容站壳子，会**稀释我们「Agent 主导的生产线 + 计费正确性」的差异化**。我们的画布应该让人一眼看到「把一件事交给 Agent，它去把片子串起来」，而不是一排平级工具入口。
2. **无管线支撑的动作项**（视频 7 项里的多数、`标记/特效/角色库/运镜`）
   → 我们**已经因为假入口砍过一轮**（`ImageNode.vue` 的注释：「宁可少放，也不摆『接入中』那种假入口」）。摆回去是**回退**；点了没反应比不摆更差。
3. **批量组不透明的多倍扣费**
   → 2×2 批量如果按他们的交互「看着是一张卡、实际花 4 份钱」，会**直接伤我们的计费正确性**。要做批量，必须在**提交前**把「这一批扣多少」讲清楚（我们已有 `preflight_check` + 服务端估算 + 付费闸门，见 `src/shared/canvas-agent-tools.ts`）。
4. **3D 导演台 / 角色造型室**
   → 重模块、独立技术栈，会**把战线拉长**，且不服务「Agent 主导」这条主线。
5. **游戏化 chrome**（双节红包倒计时、积分角标堆叠）
   → 与「专业生产线」定位拧着，倒计时条还会**抢画布注意力**。

## 5. 给产品负责人的三句话结论

- **他们最强的三处**：① 卡片**就地长出动作条**（选中即告诉用户「下一步能做什么」）；② **参数压成一行 chip**（模型位 + 参考模式位 + `16:9 · 720P · 30s · 1个`），密度高但不吵；③ **Agent 入口是「按场景起手」的完整句子**，把「该让 Agent 干什么」变成选择题而不是作文题。
- **我们最该补的三处**：① 图片卡的**「设为主图 / 下载」**——`batchChildren` / `primaryImageId` 数据模型早就有，只差 UI，性价比最高；② 视频节点**一条贴身动作条** + **Agent 空态场景化起手句**；③ 把**批量组与「设主图」**做成「提交前说清花多少钱」的批量，把计费正确性变成**可见卖点**，而不是抄他们的「一眼一张卡」。
- **一句话**：抄他们的**「就地动作 + 一行参数 + 场景起手」三种结构**，不抄他们的**广场式壳子、独家命名与无管线入口**——我们的差异化是「Agent 主导的生产线 + 每一分钱都算得清」。
